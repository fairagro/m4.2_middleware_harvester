# AI Agent Workflow

This document describes how AI coding agents (GitHub Copilot, Claude Code, Cursor, etc.)
are integrated into this project and how the supporting artifacts are structured.

---

## Overview

The workflow is built on three open standards / tools:

| Standard | Purpose | URL |
| -------- | ------- | --- |
| **agents.md** | Central entry point — gives agents project context at startup | <https://agents.md/> |
| **OpenSpec** | Spec-driven development — propose → apply → archive | <https://github.com/Fission-AI/OpenSpec> |
| **Agent Skills** | On-demand procedural knowledge — loaded by agents when relevant | <https://agentskills.io/> |

---

## IDE Integration

### GitHub Copilot (VS Code)

| Artifact | VS Code mechanism |
| -------- | ----------------- |
| `AGENTS.md` | Loaded automatically as an *instructions file*. |
| `.agents/skills/*/SKILL.md` | Skills — discovered by `description`, loaded on demand. |
| `.github/agents/*.agent.md` | Custom agents in the agent picker. |
| `.github/prompts/opsx-*.prompt.md` | OpenSpec slash commands (`/opsx-propose`, …). |
| `.github/skills/openspec-*/SKILL.md` | OpenSpec workflow skills (generated by `openspec init`). |
| `openspec/specs/**/*.md` | Read on demand via file tools / OpenSpec commands. |

### Cursor

| Artifact | Cursor mechanism |
| -------- | ---------------- |
| `AGENTS.md` | Project instructions — loaded automatically. |
| `.agents/skills/*/SKILL.md` | Agent Skills — discovered by `description`, loaded on demand. |
| `.cursor/agents/*.md` | Subagents — e.g. `/refactoring`. |
| `.cursor/commands/opsx-*.md` | OpenSpec slash commands (`/opsx-propose`, …). |
| `.cursor/skills/openspec-*/SKILL.md` | OpenSpec workflow skills (generated by `openspec init`). |
| `openspec/specs/**/*.md` | Read on demand via file tools / OpenSpec commands. |

The canonical custom-agent definitions live in [`.github/agents/`](../.github/agents/).
[`.cursor/agents/`](../.cursor/agents/) contains symbolic links to those files
so both IDEs share one source. The `tools:` frontmatter block is used by
Copilot only; Cursor ignores unknown frontmatter fields.

## OpenSpec Loop

```text
/opsx-explore  →  /opsx-propose  →  /opsx-apply  →  /opsx-archive
     (optional)      (plan)           (build)         (merge specs)
```

| Step | What it produces |
| ---- | ---------------- |
| **explore** | Understanding only — no artifacts |
| **propose** | `openspec/changes/<name>/{proposal,design,tasks}.md` + delta `specs/` |
| **apply** | Code + checked-off tasks |
| **archive** | Delta merged into `openspec/specs/`; change moved to `changes/archive/` |

Main specs under `openspec/specs/<domain>/spec.md` describe **current** behaviour.
Optional `design.md` beside a domain captures Key Decisions for that domain.

Project context and artifact rules live in [`openspec/config.yaml`](../openspec/config.yaml).

## Custom Agents

OpenSpec covers the former `spec-to-code` workflow via `/opsx-propose` →
`/opsx-apply` → `/opsx-archive`. The only remaining custom agent is for
structural refactors that are not driven by a change proposal:

| Agent | Source (edit here) | Cursor symlink |
| ----- | ------------------ | -------------- |
| `refactoring` | [`.github/agents/refactoring.agent.md`](../.github/agents/refactoring.agent.md) | `.cursor/agents/refactoring.md` |

### `refactoring` — Structural code improvements

Extract class/module, reduce coupling, move shared code — with engineering
judgment beyond the explicit request.

## Entry Point: `AGENTS.md`

[`AGENTS.md`](../AGENTS.md) is the single entry point for all AI agents. It
contains tech stack, structure, commands, and an index of OpenSpec domains.
It links to specs instead of duplicating their content.

---

## Specs: `openspec/specs/`

Specs follow [OpenSpec](https://github.com/Fission-AI/OpenSpec) conventions:
one domain folder per capability, with `spec.md` (SHALL/MUST requirements +
scenarios) and optionally `design.md` (Key Decisions).

```text
openspec/
├── config.yaml
├── specs/
│   ├── principles/           # Foundation contract
│   ├── error-handling/
│   ├── harvester-orchestration/
│   ├── csw-harvesting/
│   ├── linked-data-harvesting/
│   └── …
└── changes/
    ├── <active-change>/
    └── archive/
```

All domains live under the single `openspec/specs/` tree (flat domain IDs).
Grouping in `AGENTS.md` (project / harvester / inspire / linked_data) is
navigational only.

## Agent Skills: `.agents/skills/`

Project-specific library skills (not OpenSpec workflow skills):

```text
.agents/
└── skills/
    ├── arctrl/
    │   └── SKILL.md                  # How to use the arctrl Python library
    └── config-wrapper/
        └── SKILL.md                  # How to use ConfigWrapper / ConfigBase
```

OpenSpec workflow skills are generated under `.cursor/skills/openspec-*` and
`.github/skills/openspec-*` by `openspec init` / `openspec update`.

## Workflow in Practice

1. Load `AGENTS.md` → project context and OpenSpec domain index.
2. For new behaviour → `/opsx-propose` then `/opsx-apply` then `/opsx-archive`.
3. If the task touches an existing domain → read `openspec/specs/<domain>/`.
4. If the task needs library knowledge → load `arctrl` / `config-wrapper`.
5. After editing → `uv run ruff format middleware/` and `uv run pytest`.

### Scenario: Adding a New Config Field

1. `/opsx-propose` a change that deltas `harvester-configuration`.
2. Agent loads the `config-wrapper` skill for the Pydantic pattern.
3. `/opsx-apply` implements code + tests; `/opsx-archive` merges the delta.

### Scenario: Fixing an ARC Serialization Bug

1. Read `openspec/specs/inspire-to-arc-mapping/`.
2. Load the `arctrl` skill.
3. Edit `mapper.py`, format, run tests. If behaviour changes, propose a
   small OpenSpec change so the main spec stays accurate.

## Adding New Specs

Prefer `/opsx-propose "<change-name>"` — OpenSpec creates the change folder
and delta specs. After archive, the domain appears under `openspec/specs/`.

When you need a brand-new domain that does not exist yet, the propose step
creates it via an `ADDED` delta. Register a short link in `AGENTS.md` under
Architecture & Design after the first archive.

Refresh generated OpenSpec IDE files after upgrading the CLI:

```bash
openspec update
```
